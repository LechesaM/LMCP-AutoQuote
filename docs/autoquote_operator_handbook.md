# Operator Handbook

## Purpose
This handbook gives operators a stable reference for review, pricing, package preparation, and incident handling without changing production behavior.

## Operating Principles
- Keep certified workflow intact.
- Record evidence before judgment where possible.
- Escalate uncertainty instead of filling gaps with assumptions.
- Preserve audit trails and review notes.
- Do not bypass manual approval gates.

## Tender Review Handbook
Use this review sequence:
1. Confirm the RFQ is in-scope.
2. Check category fit against the category library.
3. Check submission method and compliance requirements.
4. Check briefing session requirements.
5. Check delivery complexity and lead time.
6. Check supplier coverage and pricing evidence.
7. Decide whether the RFQ is suitable for deeper work, manual review, or rejection.

Key notes:
- Briefing-session tenders are high-friction and should be treated carefully.
- Supply-and-delivery work is preferred.
- Missing evidence should be logged, not guessed.

## Pricing Review Handbook
Use this review sequence:
1. Confirm the supplier and product match.
2. Check whether the price is current or stale.
3. Check delivery and VAT assumptions.
4. Compare against historical pricing.
5. Apply profitability rules.
6. Record confidence and override notes.

Key notes:
- Historical price data is advisory only.
- Delivery cost assumptions must be explicit.
- Low-confidence prices should not be treated as reliable targets.

## Submission Package Handbook
Use this review sequence:
1. Confirm the submission pack contents are complete.
2. Confirm quote pricing matches the approved internal record.
3. Confirm proof documents are attached where required.
4. Confirm naming, formatting, and version control.
5. Confirm the pack is ready for manual submission handling.

Key notes:
- No automated submission.
- No skipping of proof capture.
- No silent edits after approval.

## Incident Response Guide
Use this when a control, document, or runtime behavior looks wrong:
1. Stop the affected action.
2. Record what happened.
3. Capture screenshots, file names, and timestamps if relevant.
4. Notify the responsible operator or supervisor.
5. Preserve evidence.
6. Escalate for investigation if the issue affects control integrity.

Incident examples:
- category misclassification
- stale pricing evidence
- missing proof document
- duplicate quote package
- incorrect submission status
- suspected workflow bypass

## Escalation Standard
- When in doubt, do not submit.
- When in doubt, do not overwrite evidence.
- When in doubt, escalate for manual review.
